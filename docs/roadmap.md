# Roadmap under the revised master plan

1. Finish Stage 1: user browser walkthrough, streamed UI error and cancellation behavior, explicit failure feedback, offline-disconnected check, local data export/delete check and model/VRAM status display. Keep chat history on F: by default and do not persist storage roots until the owner chooses them.
2. Stage 2: isolated execution backend with no network, bounded resources and explicit user action. Keep the UI in analysis-only mode until verified.
3. Stage 3: validated task bank with dimensions and held-out partitions, run manifests, constrained grading and a fair 1.5B-versus-7B comparison after model approval.
4. Stages 4–9: repository intelligence/debugging, then a small training experiment, later specialist roles/adapters, component contracts and advanced research in the order of the revised plan.

Stage gates are evidence based. A generated answer is a candidate until tests run in isolation; a liked answer is not automatically training data.
